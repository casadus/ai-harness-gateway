# Handoff — 2026-09-30

## Goal

Build a small Windows-first gateway for evaluating coding harnesses independently from providers and models. The public repository is intended to be `https://github.com/casadus/ai-harness-gateway.git`.

Version 1 must run the same included C# task through all eight combinations of these harnesses and providers:

| Harness | Ollama (local) | OpenRouter (cloud) |
| --- | --- | --- |
| Codex CLI | Required | Required |
| Claude Code | Required | Required |
| OpenCode | Required | Required |
| GitHub Copilot CLI | Required | Required |

The gateway runs on each developer's computer, listens on loopback, and maps explicit model aliases to an Ollama model or an OpenRouter model. It must record the harness, provider, model, and task separately so harness and model quality can be compared.

## Decisions made with the user

- Target Windows 11 machines with 16 GB RAM. Start local evaluation with `qwen3.5:9b`; verify that its configured context and tool behavior work on the target hardware. Start cloud evaluation with `anthropic/claude-sonnet-4.6` through OpenRouter.
- Use an included, disposable C# sample task for the first runs. The public repository and its release assets must contain no company code or credentials.
- Publish a single Windows setup wizard EXE through public GitHub Releases. A developer should need only that download to start installation; cloning the repo is for source development.
- Bundle the gateway and sample task in the installer. The wizard handles setup and prerequisite checks; `launch-agent.ps1` handles evaluation runs.
- Offer to install each missing prerequisite separately, after the developer approves that installation. Show clear instructions when an automatic install is unavailable.
- The first installer may be unsigned. Publish a SHA-256 checksum and document possible Windows SmartScreen prompts.
- Provide a README with installation, examples, architecture, privacy boundaries, diagnostics, and uninstall instructions. Include a comprehensive `.gitignore` and a secret scan before public releases.
- Keep the OpenRouter key out of repository files, command arguments, harness child environments, logs, and result files. Make local versus cloud routing obvious before launch.
- Keep the implementation small and modular. Do not add LiteLLM, a team-hosted gateway, Docker, Azure deployment, dashboards, automatic scoring, or automatic provider fallback in version 1.

## Agreed implementation direction

1. Build a C# gateway that runs only during an evaluation and binds to `127.0.0.1`. Use explicit route aliases and exact upstream model IDs. Implement the minimum wire formats required by the four harnesses: OpenAI Responses, Anthropic Messages, and OpenAI Chat Completions. Preserve streaming, tool calls, cancellation, and useful upstream errors. Separate route resolution, protocol forwarding, upstream authentication, and diagnostics.
2. Configure harnesses only for the launched process. Codex needs an isolated user-level `CODEX_HOME`: its provider definitions are ignored in project-level `.codex/config.toml`. Claude Code uses an Anthropic-compatible Messages path. OpenCode and Copilot CLI need their own supported provider settings. Verify the actual request paths as integration work proceeds.
3. Build one small C# fixture with a fixed prompt, expected observable result, and reset procedure. A valid run must read files, make a change, use tools, run the relevant check, and report the result. Record versions, route, outcome, tool behavior, time, and human intervention in a simple structured result.
4. Package the self-contained gateway, scripts, and fixture in a per-user Inno Setup installer. The wizard checks prerequisites and can offer approved installs. The Windows uninstaller removes gateway-owned files; it should not silently remove shared harnesses, Ollama, or model weights.
5. Log safe metadata only: timestamp, harness, route, provider, model, status, duration, and error category. Diagnostics should report versions, service and model availability, gateway health, and recent safe errors without logging prompts, source files, responses, headers, or keys.
6. Verify all eight paths on Windows 11, then repeat installation and evaluation from a downloaded release on a second 16 GB machine before publishing version 1.
